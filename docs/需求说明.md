# FT 资源管理平台需求基线

版本：1.3 · 日期：2026-09-24 · 当前范围：独立空库程序首版。

## 来源与执行边界

- 依据本任务中的用户需求、选定的第三版预览，以及 `output/FT资源管理平台开发需求与步骤表.docx`（2026-09-17，版本 1.0）。
- 用户随后明确要求先搭框架、不需要 Excel 数据、内容逐步填入，并授权按框架开发程序。真实样例不再作为前置；旧数据不导入。实施默认值和已完成范围见 [程序实现与验证](程序实现与验证.md)。
- 区分用户明确提出的需求、方案中延续的业务规则、尚未确认的实现细节。待确认项见 [待确认事项](待确认事项.md)。
- 现有原型、数据库和附件保留；不把演示内容视为真实需求，不自动导入、删除或覆盖现有数据。

## 用户已明确的需求

| 编号 | 需求 |
|---|---|
| U01 | 建立有数据库的 FT 资源整合记录平台，方便查阅、维护资料和更新进度。 |
| U02 | 管理封装厂、芯片型号、测试机、Handler、KIT、LB、Socket、DC 线。 |
| U03 | 管理 LB、Socket、Pin 针图纸；每家封装厂还要包含 LB 规范。 |
| U04 | 管理资源库存以及资源在封装厂的库存。KIT 和设备的库存范围尚待确认。 |
| U05 | 内部多人使用，封装厂人员不登录。 |
| U06 | 手机可在公司外查看和更新，电脑端同时可用。 |
| U07 | 现有资料主要在 Excel；公司允许图纸上云。 |
| U08 | 主要浏览层级按封装厂、芯片型号、设备及配套资源由大到小组织。 |
| U09 | 快捷入口包括芯片型号、封装厂、库存总览、图纸中心、进度事项。 |
| U10 | 使用第三版表格工作台的视觉方向；逐步开发、验证并由用户确认。 |

## 业务层级

```text
封装厂
├── LB 规范
│   └── 适用范围、版本、状态、附件、历史版本
└── 芯片型号
    ├── Handler
    │   └── KIT
    └── 测试机
        ├── LB
        │   └── LB 图纸与版本
        ├── Socket
        │   ├── Socket 图纸与版本
        │   └── Pin 针规格、图纸与版本
        └── DC 线
```

“产品”在页面中统一称为“芯片型号”。LB 规范位于工厂层级，与芯片型号并列；资源详情可以引用规范，但不改变其工厂归属。

## 入口与页面范围

| 入口 | 主要内容 |
|---|---|
| 芯片型号 | 跨工厂查询型号、封装形式、测试配置、配套资源、图纸及进度。 |
| 封装厂 | 工厂资料；芯片型号、LB 规范、工厂库存、进度四类内容。 |
| 库存总览 | 按类型、型号、版本、地点、状态筛选；查看数量与流转。 |
| 图纸中心 | LB、Socket、Pin 针图纸和 LB 规范；关联、版本、预览及下载。 |
| 进度事项 | 事项、负责人、状态、计划日期、最新进展及历史。 |

电脑端采用深蓝侧栏、白色内容区、筛选栏和表格；手机端将宽表转换为卡片。示例图只确定视觉方向，图中的数值、日期、设备库存、状态和统计指标不构成要求。

## 沿用开发步骤表的业务规则

| 编号 | 规则 |
|---|---|
| R01 | 层级用于浏览；共用资源在数据库只保留一份档案。 |
| R02 | 同一芯片可对应多个工厂；同一资源型号可服务多个芯片。 |
| R03 | 同厂同芯片允许多套完整测试配置，记录 Handler、KIT、测试机、LB、Socket、DC 线及验证状态；具体必填和可选条件在样例分析时确认。 |
| R04 | 共用库存不按芯片重复累计；默认查看该厂该型号共享数量。专用分配或预留不在本轮新增。 |
| R05 | LB 规范属于工厂，可限定适用测试机，配置关联实际采用的版本。 |
| R06 | 新图纸和新规范新增版本，旧配置保持旧版关联，不自动覆盖。 |
| R07 | 自有仓库和工厂库存使用一套数据，以存放地点区分。 |
| R08 | 数量变更经业务操作产生流水，保留操作人、时间和原因；不直接无痕覆盖库存。 |
| R09 | 防止负库存、重复提交和并发扣减错误；多人修改冲突需提示。 |
| R10 | 电脑和手机使用同一数据库、权限和业务规则。 |
| R11 | 私有附件的预览、下载均检查权限，不能仅隐藏页面入口。 |
| R12 | 已引用档案优先停用，历史流水和文档版本不得随意删除。 |

## 第一版功能边界

1. 基础档案：工厂、地点、芯片型号、测试机、Handler、LB、Socket、DC 线、KIT，支持维护、搜索和停用。
2. 配套配置：关联工厂与芯片，保存多套设备和配套资源组合及验证状态。
3. 图纸与规范：上传、关联、版本、发布状态、历史、预览与下载；支持的文件类型待确认。
4. 库存：期初入库、状态调整、盘点、报废及流水；追踪粒度和类型范围待确认。
5. 调拨：发出、在途、分批签收和差异记录；发出扣来源，签收增目标，未签收留在途。
6. 进度：负责人、计划完成日期、状态、更新历史和附件，具体类别与状态待确认。
7. Excel：模板、字段映射、校验、重复判断、导入预览、错误报告和导出。
8. 多人协作：登录、权限、操作记录，具体角色范围待确认；不延续原型匿名访客作为默认要求。
9. 手机：查询、图纸查看、进度更新、照片上传和签收。
10. 运维：云端 HTTPS、私有文件存储、数据库与附件备份及恢复验证。

暂缓原生 App、采购财务、复杂审批、完整维修工单、Pin 针消耗寿命、工厂外部账号、企业微信集成、复杂工程图在线编辑。这些并非本次新增任务。

## 技术与数据保护

Vue 3 + TypeScript、Django REST Framework、PostgreSQL 和私有对象存储是原方案建议，尚未实施或锁定。现有项目实际为本地原型及保留的 Web 脚手架，详见 [项目现状](项目现状.md)。第 03 步提出复用与迁移建议，第 05 步前明确，不在第 01 步重写。

现有 SQLite 文件来源尚未确认，全部按需保护数据处理。启动原型会执行初始化和种子逻辑，本步骤不启动、不运行可能改库的验证或清理脚本。未来迁移前先备份、核对映射并在副本验证。

## 完整业务验收路径

导入档案 → 建立配置 → 期初入库 → 发往工厂 → 手机分批签收 → 新增图纸版本 → 更新验证事项 → 查询库存和历史。

同时检查共用库存不重复、未授权文件访问被拒绝、并发与重复提交正确处理、旧版可访问、数据库和附件可恢复。每阶段条件见 [验收清单](验收清单.md)。
