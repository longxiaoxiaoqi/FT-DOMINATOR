## 最新授权与实施范围

用户明确要求先搭框架、不需要 Excel 输入、内容后续自行填入，并要求按该框架开发程序。第 02 步真实样例验收不再是实现前置；后续阶段按可运行框架合并推进，而非继续等待资料。

新增目录 `platform/`，不重写旧 `prototype/`。原型、SQLite 数据和 Word 保留。交付库为空，管理员在首次启动时创建；没有固定初始账号或示例库存。

本轮落实的默认规则：LB、Socket、DC 线、KIT 数量管理；测试机、Handler、Pin 针为资料档案；角色为管理员、编辑、只读；所有内部登录均需账号；其他特殊业务可再调整，不进行旧库迁移。

## 实现结构

| 文件或目录 | 内容 |
|---|---|
| platform/core/models.py、migrations/ | 工厂、地点、芯片、资源、配置、图纸版本、附件、库存、调拨、事项、审计的关系和约束 |
| platform/core/api.py | 登录、档案接口、冲突检查、附件权限、事务库存和用户管理 |
| platform/static/、templates/ | 第三版风格页面、录入表单、表格、详情和手机卡片 |
| platform/serve.py、start.bat、start.ps1 | Waitress 服务与 Windows 一键启动 |
| platform/core/tests.py | 独立临时库业务与权限测试 |
| platform/backup.py | 停服状态下的 SQLite 与附件配套备份 |
| platform/Dockerfile、compose.yaml | 待验证的云服务器部署配置 |

技术路线采用 Django、独立 SQLite 与原生浏览器界面，避免依赖旧脚手架。Vue、PostgreSQL 和对象存储并未在本机实现为运行依赖；PostgreSQL 环境配置接口已预留，不能将预留等同于测试通过。
